# 04 — ადმინ პანელი

ადმინ პანელი აგებულია **Payload CMS 3**-ზე (`/admin`). Payload კოლექციის აღწერიდან ავტომატურად ქმნის
სიებს, ფილტრებს, ძებნას, ფორმებს, ვერსიებს, დრაფტებს და წვდომის კონტროლს. ჩვენ ვამატებთ **საკუთარ
ეკრანებს** იქ, სადაც სტანდარტული ფორმა საკმარისი არ არის.

**მთავარი პრინციპი: ადმინი ტელეფონიდან უნდა მუშაობდეს.** პატარა მაღაზიაში მეპატრონე ხშირად დახლთანაა,
ამიტომ ყველაზე ხშირი მოქმედებები ტელეფონით ერთი ხელით უნდა სრულდებოდეს: ნივთის დამატება ფოტოებით,
მაღაზიაში გაყიდვის აღნიშვნა, შეკვეთის გაგზავნა, ქირის გაცემა/მიღება.

ინტერფეისი ქართულად, ZoyToy-ს ფერებით, მაგრამ მშვიდი და ფუნქციური.

## ნივთის მართვა (CRUD)

### სწრაფი დამატება (ტელეფონიდან, ~2 წუთი)
1. **ფოტოები** — კამერით ან გალერეიდან, რამდენიმე ერთად (იხ. [ფოტოები](#ფოტოები-ატვირთვა-ჭრა-ხარისხის-კონტროლი)).
2. **სახელი, კატეგორია, ფასი, მდგომარეობა** — მდგომარეობა დიდი ღილაკებით (ახალი · ახალი, გახსნილი · როგორც ახალი · ძალიან კარგი · კარგი · ნორმალური).
3. **ასაკი, ფრენჩაიზი** — სწრაფი არჩევანი ბოლოს გამოყენებულებიდან.
4. „შენახვა როგორც დრაფტი“ ან „გამოქვეყნება“. სისტემა ანიჭებს SKU-ს → **დაბეჭდე ეტიკეტი** (QR + ფასი) ნივთზე დასაკრავად.

დანარჩენ ველებს (აღწერა, ხარვეზები, წონა, ინგლისური თარგმანი) მოგვიანებით, კომპიუტერიდან ავსებენ. გამოქვეყნებამდე ჩანს **სისრულის ინდიკატორი**.

### სრული ფორმა (ჩანართებით)
1. **ძირითადი** — სახელი (ka/en/ru), slug, აღწერები, ბრენდი, ფრენჩაიზები, კატეგორიები, ასაკი, თეგები, წარმოშობა (აშშ/ევროპა).
2. **მდგომარეობა** — მდგომარეობა, შენიშვნა, ხარვეზები (ტექსტი + ფოტო), სისრულე (აკლია ნაწილები?, ყუთი, ინსტრუქცია), „შემოწმებულია, მუშაობს“, ელემენტები, „გაწმენდილია“ (თარიღი), „ახლის ფასი დაახლ.“.
3. **მედია** — ფოტოები, ჭრა, მთავარი ფოტოს არჩევა, ფონის მოცილება (არჩევითი).
4. **ყიდვა** — ფასი, ძველი ფასი, მარაგი ფილიალების მიხედვით (უნიკალურისთვის = 1).
5. **ქირა** — ჩართვა, დღიური ფასი, დეპოზიტი (ნაგულისხმევი = ღირებულება), მინ/მაქს დღეები, ეგზემპლარები (+ QR).
6. **მიწოდება** — წონა, ზომები, მყიფე (კატეგორიის ნაგულისხმევიდან ივსება).
7. **თამაშები** — რომელ კამპანიებშია; „შექმენი კამპანია“.
8. **SEO** — სათაური, აღწერა, OG სურათი (ავტომატური).

- დრაფტი → გამოქვეყნება, დაგეგმილი გამოქვეყნება, ვერსიების ისტორია, „ნახე საიტზე“ პრევიუ, **დუბლირება** (მსგავსი ნივთისთვის).
- **გაყიდული ნივთი** → სტატუსი `sold` ავტომატურად; 30 დღის შემდეგ `archived`. ხელით „დაბრუნება გაყიდვაში“ (თუ მყიდველმა დააბრუნა).
- წაშლა = არქივი (soft delete). სრული წაშლა მხოლოდ admin როლით და მხოლოდ შეკვეთის გარეშე ნივთზე.
- **CSV/Excel იმპორტი** — საწყისი ~1 000 ნივთისთვის (ფოტოები საქაღალდიდან SKU-ით დასახელებული ფაილებით).

### სია
ცხრილი: ფოტო, სახელი, SKU, ფასი, მდგომარეობა, მარაგი/ფილიალი, ქირა?, თამაში?, სტატუსი, დღეები თაროზე.
ფილტრები, ძებნა სახელით/SKU-ით/QR სკანით, მასობრივი მოქმედებები (გამოქვეყნება, კატეგორია, ფასის ცვლილება %, კამპანიაზე მიბმა, არქივი).

## ფოტოები: ატვირთვა, ჭრა, ხარისხის კონტროლი

მეპატრონე იღებს პროფესიონალური აპარატით ან ტელეფონით. სისტემის ამოცანაა, რომ **ნებისმიერი ფოტო ბარათზე ერთნაირად ლამაზად ჩანდეს**.

**ატვირთვისას ავტომატურად:**
- iPhone-ის **HEIC** ფორმატი → JPEG (ბრაუზერშივე, ატვირთვამდე)
- ორიენტაციის გასწორება EXIF-ით, შემდეგ **EXIF/GPS მეტამონაცემების წაშლა** (კონფიდენციალურობა)
- მაქს. 2400px-მდე შემცირება, ზომების გენერაცია (ბარათი, გალერეა, zoom) AVIF/WebP-ად, ბუნდოვანი წინასწარი ჩვენება (blurhash)

**შეზღუდვები (ვალიდაცია):**
| წესი | რატომ |
|------|-------|
| მთავარი ფოტო მინ. **1200 × 1200px** | zoom-ზე და დიდ ეკრანზე არ გაბუნდოვანდეს |
| მთავარი ფოტოს ჭრა — **ჩაკეტილი 1:1 კვადრატზე** | ყველა ბარათი ერთი ფორმისაა |
| გალერეის ფოტოები — 1:1 ან 4:5 | ერთიანი გალერეა |
| ფაილი ≤ 25 MB, მხოლოდ JPEG/PNG/WebP/HEIC | |
| მინ. 3 ფოტო გამოქვეყნებისთვის (გაფრთხილება, არა ბლოკი) | მეორადზე ნდობისთვის |
| ხარვეზის აღწერას ახლავს ფოტო | |

**ჭრის რედაქტორი:** Payload-ს ჩაშენებული აქვს ჭრა (crop) და ფოკუსის წერტილი; ჩვენ ვამატებთ **ფიქსირებულ თანაფარდობას**
(1:1 მთავარზე), ბადეს (rule of thirds), „ცენტრში მოთავსება“ ღილაკს და ბარათის **ცოცხალ პრევიუს** — ადმინი ხედავს,
როგორ გამოჩნდება ფოტო ბარათზე, სანამ შეინახავს.

**ბარათზე ერთიანი ხედი** (კოდის მხარე): ბარათის სურათის ზონა ყოველთვის 1:1; ფოტო ჩაისმება `contain`-ით, მცირე
დაშორებით, კატეგორიის ფერის ღია ფონზე → ზედმეტი ფონი არ ჩანს და განსხვავებული ფოტოები ერთ სტილში იკითხება.
თუ ნივთს **ფონმოცილებული** ვერსია აქვს, ის გამოიყენება (საუკეთესო შედეგი). სათაური მაქს. 2 ხაზი, ფასის ხაზი ყოველთვის
ერთ სიმაღლეზე, მაქს. 2 ბეჯი.

**ფონის მოცილება:** MVP-ში — ღილაკი „ფონის მოცილება“ თითო ფოტოზე (ღია მოდელი საკუთარ სერვერზე, ან ფასიანი API
თითო ფოტოზე — 1 000 ნივთზე ხარჯი უნდა შევადაროთ; ალტერნატივა — Photoshop-ის batch action-ით წინასწარ).
ფაზა 2 — ავტომატურად მთავარ ფოტოზე.

**ფოტოს გადაღების მოკლე გზამკვლევი** (ადმინში „დახმარება“ ღილაკით): თეთრი ან ღია ერთფეროვანი ფონი, დღის შუქი ან
softbox, ნივთი ჩარჩოს ~80%, ყოველთვის ერთი და იგივე მანძილი, ტელეფონზე „Portrait“ რეჟიმი გამორთული, ცალკე ფოტო
ხარვეზზე და ზომის გასაგებად (ხელში დაჭერილი).

## მარაგი და ფილიალები

- **ფილიალი** (`Location`): სახელი, მისამართი, საათები, გატანის წერტილია თუ არა. MVP-ში — ერთი (ბათუმი), ინტერფეისში ფილიალის ველი დამალულია, სანამ მეორე არ დაემატება.
- მარაგი ინახება **ფილიალის მიხედვით**; პროდუქტის გვერდზე ჩანს „მარაგშია: ბათუმი, რუსთაველის ქ.“ — მეორე ფილიალის შემთხვევაში მყიდველი ირჩევს გატანის წერტილს.
- **ფილიალებს შორის გადატანა** — ერთი მოქმედება („გადაიტანე ფილიალ B-ში“), ისტორიით.
- ყველა ცვლილება იწერება `StockMovement`-ში: ვინ, როდის, რატომ (ონლაინ შეკვეთა / მაღაზიაში გაყიდვა / დაბრუნება / კორექტირება).

## მაღაზიაში გაყიდვა (ტელეფონიდან)

სალაროს პროგრამა არ არის, ამიტომ ეს ეკრანი მისი მარტივი ჩამნაცვლებელია. მთავარი მიზანია, რომ **ონლაინ და ოფლაინ გაყიდვები ერთმანეთს არ დაეჯახოს**.

1. ღილაკი „🛒 მაღაზიაში გაყიდვა“ → **QR ეტიკეტის სკანირება** კამერით (ან ძებნა სახელით/SKU-ით).
2. ნივთის ბარათი: ფოტო, ფასი, მდგომარეობა და **სტატუსი**:
   - 🟢 თავისუფალია → „გაყიდულია“ (არჩევითი: ფასდაკლება, გადახდის ტიპი: ნაღდი/ბარათი, მყიდველის ტელეფონი).
   - 🟡 ვიღაცის კალათაშია (ჯერ არ გადაუხდია) → შეიძლება გაყიდო, ონლაინ კალათიდან ავტომატურად ამოვარდება.
   - 🔴 **ონლაინ გადახდილია** → გაყიდვა დაბლოკილია: „ეს ნივთი შეკვეთა ZT-000123-შია — გადადე“.
3. გაყიდვის შემდეგ საიტზე ნივთი **მყისიერად** ქრება (`sold`).
4. დღის ბოლოს: „დღის ანგარიში“ — მაღაზიაში გაყიდულები, ნაღდი/ბარათი.

**Telegram ბოტი** მაღაზიისთვის: ყოველი ონლაინ გადახდისას — „📦 ახალი შეკვეთა: [ფოტო] LEGO ციხე, ZT-000123, თარო B3 — ჩამოიღე“ + ღილაკი „ჩამოღებულია ✅“.

## შეკვეთები და მიწოდება

- სია სტატუსის ჩანართებით + ფილტრები (მიწოდების მეთოდი, ქალაქი, გადახდის სტატუსი, თარიღი).
- შეკვეთის გვერდი: ნივთები (snapshot), გადახდები, ისტორია, კლიენტი, მისამართი, შიდა კომენტარები.
- **გაგზავნის ოსტატი მეთოდის მიხედვით:**
  - *გატანა* → „მზადაა“ → მყიდველს SMS → „გატანილია“ (+ ნაღდით გადახდის აღნიშვნა).
  - *ბათუმის კურიერი* → კურიერის სერვისი (Glovo/Wolt/საკუთარი) + კომენტარი → „გაგზავნილია“ → „ჩაბარდა“.
  - *საქართველოს ფოსტა* → თრექინგის ნომერი → მყიდველს SMS ბმულით.
  - *ავტობუსი* → ქალაქი, მძღოლის ტელეფონი, გასვლის და მოსალოდნელი ჩასვლის დრო → მყიდველს SMS ყველა დეტალით.
- **თანხის დაბრუნება** (სრული/ნაწილობრივი) ბანკის API-ით — BOG-ით გადახდილზე BOG-ით, TBC-ით — TBC-ით (სისტემა თავად არჩევს).
- მიწოდების ფურცლის/ინვოისის ბეჭდვა (PDF).

## გაქირავების ოპერაციები

- **კალენდარი:** რიგები = ეგზემპლარები, ზოლები = ქირავნობები, ბუფერი (1 დღე) ღია ფერით.
- **„დღეს“ ეკრანი:** გასაცემი / დასაბრუნებელი / დაგვიანებული.
- **სკანერი:** QR → კონტექსტური მოქმედება (გაცემა / მიღება / გაწმენდა დასრულდა / რემონტი).
- **მიღების ოსტატი:** ფოტოები → ჩეკლისტი → დაქვითვები (დაგვიანება ავტომატურად; დაზიანების კატეგორია; დაკარგვა; გაწმენდა) → ჩანს „დასაბრუნებელი დეპოზიტი: X ₾“ → დადასტურება → სისტემა თავად აბრუნებს თანხას ბანკის API-ით (ან ნაღდის შემთხვევაში — „ნაღდით დაბრუნდა“).
- **გამოსყიდვა** ადგილზე: „იყიდა“ → გამოთვლილი ფასი, დეპოზიტის ჩათვლით.
