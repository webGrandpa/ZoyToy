# 09 — სადემო ვერსია Vercel-ზე

> **მიზანი:** დამკვეთი ინტერნეტში ხედავს ცვლილებებს, სანამ ვამუშავებთ. ეს **სადემო** გარემოა: Vercel-ის უფასო (Hobby)
> გეგმა არაკომერციულია ([08 §2](08-lite-mvp.md#2-უფასო-ინფრასტრუქტურა), [01](01-architecture.md)) — ნამდვილი მაღაზიის
> გაშვებისას გადავდივართ 08 §2-ის გეგმაზე ან Vercel Pro-ზე. კოდი ორივეს უჭერს მხარს.

## 1. რა სად არის

**მისამართი:** https://zoytoy.vercel.app (ადმინი — `/admin`)

| ნაწილი | სად | ცვლადი |
|--------|-----|--------|
| საიტი + `/admin` | Vercel პროექტი `zoytoy`, ფუნქციები ფრანკფურტში (`fra1`, `apps/web/vercel.json`) | — |
| ბაზა | Neon Postgres, Vercel → Storage-იდან (ფრანკფურტი) | `DATABASE_URL` (ავტომატურად) |
| ფოტოები | Vercel Blob, საქაღალდე `media/`; ადმინი ფოტოს პირდაპირ ბრაუზერიდან ტვირთავს, ამიტომ ტელეფონის დიდ ფოტოებს Vercel-ის 4.5 MB-იანი ლიმიტი არ ეხება; ზომებს (thumb/card/large) სერვერი ჭრის | `BLOB_READ_WRITE_TOKEN` (ავტომატურად) |
| სესიების და თამაშის ტოკენების გასაღები | ხელით: Settings → Environment Variables | `PAYLOAD_SECRET` |
| დილის სამუშაო: ვადაგასული ჯავშნები თაროზე + შეჯამება Telegram-ში | Vercel Cron `/api/cron/daily`, ყოველდღე 06:00 UTC = 10:00 ბათუმში | `CRON_SECRET` (არასავალდებულო) |
| Telegram ბოტი (§5) | შეკვეთები ღილაკებით, მესიჯები მყიდველს, შეჯამება | `TELEGRAM_BOT_TOKEN`; ჩატი — ადმინში |
| საიტის მისამართი QR ეტიკეტებზე, sitemap-ში, canonical-ში | ავტომატურად `zoytoy.vercel.app`; საკუთარ დომენზე — **ჯერ** დააყენე, მერე დაბეჭდე ეტიკეტები | `SITE_URL=https://…` |

- `*.vercel.app` მისამართები Google-ში არ ჩანს (`X-Robots-Tag: noindex`, `next.config.ts`); საკუთარი დომენი ჩვეულებრივ ინდექსირდება.
- ლოკალურად (`BLOB_READ_WRITE_TOKEN`-ის გარეშე) ფოტოები ისევ `apps/web/media`-ში ინახება.

## 2. ერთჯერადი მომზადება

1. **ბაზა** — Vercel → `zoytoy` → Storage → Create Database → **Neon** → რეგიონი Frankfurt → Free → Connect (ყველა გარემო).
2. **ფოტოები** — Storage → Create → **Blob** → Frankfurt → **Public** → Connect. შემდეგ საცავის **Projects** ჩანართი → ⋯
   პროექტის გვერდით → **Update Project Connection** → ✔ „Add a read-write token env var to this connection“.
   ახალი კავშირი ნაგულისხმევად OIDC-ზეა (მხოლოდ `BLOB_STORE_ID`), Payload-ის ადაპტერს (3.93) და ბრაუზერიდან პირდაპირ
   ატვირთვას (`handleUpload`) კი `BLOB_READ_WRITE_TOKEN` სჭირდება.
3. **გასაღები** — რეპოს ფესვიდან: `openssl rand -hex 32 | vercel env add PAYLOAD_SECRET --environment production --sensitive --yes`
   (ან Settings → Environment Variables-ში ნებისმიერი გრძელი შემთხვევითი სტრიქონი). გასაღების შეცვლა ყველას გამოიყვანს ადმინიდან.
4. **სადემო ნივთები** (ერთხელ) — `vercel deploy --prod --build-env SEED_DEMO=1`: აწყობისას Vercel-ზევე იწერება
   კატალოგი და ფოტოები Blob-ში. ბაზის გასაღებები კომპიუტერზე არ ჩამოდის, ადმინის ანგარიში არ იქმნება, უკვე შევსებულ
   ბაზას არ ეხება. ჩვეულებრივ deploy-ში (`SEED_DEMO`-ს გარეშე) ეს ნაბიჯი არ ეშვება.
5. **პირველი ადმინი — მაშინვე** — `/admin` → „პირველი მომხმარებლის შექმნა“ (ელფოსტა და პაროლი თავად მფლობელი ირჩევს).
   სანამ პირველი ანგარიში არ შექმნილა, ამ გვერდს ნებისმიერი ვიზიტორი ხედავს.

## 3. განახლება

- **თავისით:** ყოველი push `main`-ზე (GitHub `webGrandpa/ZoyToy`, დაკავშირებულია Vercel-თან) ~3 წუთში საიტზე ჩანს.
  ხელით, საჭიროების შემთხვევაში: რეპოს ფესვიდან `vercel deploy --prod`.
- **შინაარსი:** ადმინში შენახული ცვლილება (ნივთი, კატეგორია, ფოტო, ფილიალი, კამპანია, საიტის პარამეტრები)
  მაღაზიის გვერდებზე მაშინვე ჩანს — ქეშირებულ გვერდებს ჰუკი აახლებს (`apps/web/src/lib/refresh.ts`).
- Build: `apps/web/scripts/vercel-build.sh` — ჯერ ბაზის მიგრაციები, მერე Next.js (`NODE_ENV=production`).
- იტვირთება მხოლოდ `.vercelignore`-ით დაშვებული: `apps/`, `packages/`, ფესვის package/lock/workspace ფაილები.
  `.env`, `media/`, ტესტები და build-ის ნარჩენები — არასდროს.

## 4. ბაზის სქემის ცვლილება — აუცილებელი წესი

ლოკალურად Payload სქემას პირდაპირ ცვლის (push). **ონლაინ ბაზა იცვლება მხოლოდ მიგრაციით.** ყოველი კოლექციის/ველის
ცვლილების შემდეგ, deploy-მდე:

```bash
pnpm --filter @zoytoy/web payload migrate:create <მოკლე-სახელი>   # → apps/web/src/migrations/
```

მიგრაციის გარეშე ონლაინ საიტი ახალ ველზე შეცდომას აჩვენებს. ძველ მიგრაციებს არ ვცვლით — მხოლოდ ახალს ვამატებთ.
პირდაპირი ცვლილება (push) ჩართულია მხოლოდ ლოკალურ ბაზაზე (`localhost` / `127.0.0.1`) — `payload.config.ts`.

## 5. Telegram ბოტი

**რას აკეთებს** (docs/08 §3.2): ახალი შეკვეთა ჩატში მოდის პირველი ნივთის ფოტოთი, ფასით, ქალაქით, ნომრითა და ღილაკებით —
`✅ დადასტურება` → `💰 გადახდილია` → `📦 გაიგზავნა` / `🏁 გაიტანა` → `🏁 ჩაბარდა`, ან `❌ გაუქმება` (ჯერ კითხულობს „დიახ/არა“).
ღილაკზე დაჭერა შეკვეთის სტატუსს ცვლის და საიტზე ნივთიც თავისით გადადის (დაჯავშნილი → გაყიდული / თაროზე).
`💬 WhatsApp` მყიდველის ჩატს ხსნის ამ ეტაპის მზა ტექსტით მისსავე ენაზე, `📞 დარეკვა` ტელეფონს რეკავს,
`🎟` ჯილდოს კოდს გამოყენებულად ნიშნავს (ბარათში ჩანს, მოქმედებს თუ არა და რამდენი გამოდის ფასდაკლებით).
ბრძანებები: `/orders` ღია შეკვეთები · `/digest` შეჯამება ახლავე · `/code ZOY-…` ან უბრალოდ კოდი — ჯილდოს შემოწმება.
ყოველ დილას 10:00-ზე — შეჯამება: დაუდასტურებელი მოთხოვნები (WhatsApp ღილაკით), გადაუხდელი, გასაგზავნი, ბოლო 24 სთ.

**დაყენება (ერთხელ, ~3 წუთი):**
1. Telegram-ში @BotFather → `/newbot` → სახელი (მაგ. „Zoy Toy მაღაზია“) → username (მაგ. `zoytoy_shop_bot`) → მოგცემს ტოკენს.
2. რეპოს ფესვიდან: `vercel env add TELEGRAM_BOT_TOKEN --environment production --sensitive` და ჩასვი ტოკენი.
3. ახალი ატვირთვა (ნებისმიერი push `main`-ზე ან `vercel deploy --prod`) — build-ის ლოგში: `Telegram: @… → https://…/api/telegram/webhook`.
4. ადმინი → საიტის პარამეტრები → Telegram → „📱 პირად ჩატთან დაკავშირება“ (ან „👥 ჯგუფთან დაკავშირება“ — თანამშრომლებთან ერთად)
   → Telegram იხსნება → **Start** (ჯგუფისთვის აირჩიე ჯგუფი) → ბოტი ნომერს თავისით ჩაწერს და მოგწერს „✅ დაკავშირდა“.
   ბმული ხელმოწერილია და 30 წუთი მოქმედებს; ღილაკებს მხოლოდ ადმინი ხედავს. ხელითაც შეიძლება: ბოტს `/start` → ნომერი → „ჩატის ნომერი“.
5. შეამოწმე: იმავე ბლოკში „🧪 სატესტო შეტყობინება“, ან საიტზე სატესტო შეკვეთა → ჩატში მოვა ბარათი.
   ბლოკი Telegram-ს ეკითხება და აჩვენებს, მუშაობს თუ არა კავშირი: ნომერი ვერ მოიძებნა, ბოტი დაბლოკილია, ჯგუფიდან ამოაგდეს.
   ჯგუფს რომ Telegram სუპერჯგუფად გადააკეთებს (ნომერი იცვლება), ბოტი ახალ ნომერს თავისით გადაიწერს.

**უსაფრთხოება:** webhook-ის საიდუმლო და „დარეკვის“ ბმულის ხელმოწერა `PAYLOAD_SECRET`-იდან გამოითვლება (ცალკე ცვლადი
არ სჭირდება); ღილაკებს და ბრძანებებს მხოლოდ ადმინში მითითებული ჩატი იყენებს, სხვა ჩატი `/start`-ზე მხოლოდ საკუთარ
ნომერს იგებს. `CRON_SECRET`-ის დაყენებისას `/api/cron/daily`-ს მხოლოდ Vercel იძახებს; მის გარეშე ის უვნებელია —
შეჯამება 20 საათში ერთხელ მიდის და მხოლოდ დილით. რეკომენდებულია მაინც დაყენება: `openssl rand -hex 32 | vercel env add CRON_SECRET --environment production --sensitive`.

**ტექსტები:** ადმინი → საიტის პარამეტრები → შეტყობინებები (ზემოთ ენის გადამრთველით ka/ru/en); ცარიელი ველი =
სტანდარტული ტექსტი. იგივე ტექსტები შეკვეთის გვერდზეა ღილაკებით WhatsApp / Telegram / კოპირება.
კოდი: `apps/web/src/lib/telegram/` (ბოტი, ბარათები, შაბლონები), `src/endpoints/telegram.ts`, `scripts/telegram-setup.ts`.
